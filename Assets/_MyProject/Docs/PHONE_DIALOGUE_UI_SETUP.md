# Phone Dialogue UI: настройка и диагностика

Этот документ описывает телефонный экран переписки, его scene-ссылки, шаблоны SMS-бабблов, layout-поля и быстрый preview.

## Где настраивать

Главный компонент для сценной настройки телефона: `StoryUserInterface`.

`StoryUiStyle` может показывать вкладку `Телефон` и быстрые кнопки preview, но важные ссылки сцены должны жить в `StoryUserInterface`: `PhoneDialogueUI`, `Panel`, `Safe Area`, `ScrollRect`, `Content`, шаблоны incoming/outgoing/photo и тексты внутри шаблонов.

Если старые ссылки остались в `PhoneDialogueUI` или `StoryUiStyle`, нажми:

- `Мигрировать ссылки из StoryUiStyle`
- `Автозаполнить ссылки телефона`
- `Проверить ссылки телефона`

После изменения layout нажимай `Показать preview` или `Пересчитать layout`.

## Ссылки UI телефона

- `PhoneDialogueUI` - runtime-компонент телефона в сцене.
- `Root preview` - корневой объект экрана телефона, который включается при preview/runtime.
- `Root экрана телефона` - верхний RectTransform визуального телефона.
- `Safe Area` - зона внутри телефона; к ней применяется `Safe Area Padding`.
- `Header` - верхняя панель телефона.
- `Кнопка назад` - кнопка закрытия/возврата.
- `Имя контакта в header` - TMP_Text имени контакта сверху.
- `Аватар контакта в header` - аватар только в верхней панели, не в бабблах.
- `ScrollRect сообщений` - ScrollRect переписки.
- `Viewport сообщений` - viewport; по его ширине считается максимальная ширина бабблов.
- `Content сообщений` - сюда спавнятся реальные копии сообщений.
- `Панель ввода` - нижняя декоративная панель ввода.
- `Placeholder ввода` и `Текст ввода` - тексты input bar.

## Шаблоны сообщений

Есть три независимых шаблона:

- `Incoming шаблон`
- `Outgoing шаблон`
- `Photo шаблон`

У каждого шаблона должны быть свои ссылки:

- `Root шаблона` - выключенный объект-шаблон. Он копируется при спавне, сам шаблон не должен быть видимым как сообщение.
- `Текст имени отправителя` - TMP_Text имени внутри баббла.
- `Контейнер баббла` - RectTransform тела баббла; ему задаются размер и `Сдвиг баббла`.
- `Фон баббла` - Image подложки баббла.
- `Текст сообщения` - TMP_Text основного текста.
- `Круг аватара` и `Аватар` - объекты аватара в шаблоне. Для SMS обычно скрыты.
- `Image вложения` - Image для фото-вложения, если сообщение реально содержит attachment.
- `LayoutElement строки` - LayoutElement на root строки.
- `LayoutGroup строки` - группа строки; через неё применяются alignment, spacing и `Padding строки`.
- `LayoutGroup контейнера` и `ContentSizeFitter контейнера` - если шаблон использует автосайзинг.

Важно: incoming и outgoing не должны использовать один общий баббл. У синего и серого баббла должны быть отдельные root/template-ссылки.

## Кто с какой стороны

В quick preview:

- контакт, например `Мэг: Привет`, считается incoming: сообщение слева и обычно рисуется синей подложкой;
- игрок, `{PlayerName}: С кем?`, `NAME: ...`, `ИМЯ: ...`, считается outgoing: сообщение справа и обычно рисуется тёмной/текущей подложкой игрока.

Имя в баббле теперь хранится отдельно в `PhoneMessage.senderName`.
`side` выбирает шаблон/раскладку, а не является единственным источником имени.
Для героини используй `{PlayerName}`: в runtime и preview оно подставляется из сохранения текущей истории или default имени истории. Если сохранённого имени нет, используется fallback `Героиня`.

Если стороны выглядят наоборот, проверь, какие шаблоны назначены в `Incoming шаблон` и `Outgoing шаблон`.

## Layout сообщений

Глобальные поля:

- `Safe Area Padding` - X=лево, Y=верх, Z=право, W=низ для safe area.
- `Padding Content сообщений` - X=лево, Y=верх, Z=право, W=низ для всего списка сообщений. Это главный способ отодвинуть чат от краёв телефона.
- `Вертикальный зазор сообщений` - расстояние между строками в Content.
- `Горизонтальный offset баббла` - общий X-сдвиг баббла. Плюс двигает вправо, минус двигает влево.
- `Incoming Horizontal Offset` - отдельный X-сдвиг для входящих сообщений. `0` значит использовать `Incoming Layout`, затем общий fallback.
- `Outgoing Horizontal Offset` - отдельный X-сдвиг для исходящих сообщений. `0` значит использовать `Outgoing Layout`, затем общий fallback.
- `Photo Horizontal Offset` - отдельный X-сдвиг для фото-сообщений. `0` значит использовать `Photo Layout`, затем общий fallback.
- `Padding баббла сверху/снизу/слева/справа` - внутренние отступы текста.
- `Макс. ширина баббла` - доля ширины viewport, например `0.74`.
- `Мин. ширина баббла` - минимальная ширина коротких сообщений.
- `Сдвиг текста` - общий X/Y-сдвиг текста внутри баббла.
- `Размер фото` - базовый размер фото-вложения.
- `Скроллить вниз` - автоматически прокручивать переписку к последнему сообщению.
- `Показывать имена в бабблах` - глобально включает имена во всех бабблах. Для точной настройки можно выключить это поле и включать `Показывать имя` отдельно в `Incoming Layout`, `Outgoing Layout` или `Photo Layout`.
- `Скрывать аватары в бабблах` - глобально выключает головы/аватары в сообщениях.
- `Принудительный Vertical Layout` - применяет настройки VerticalLayoutGroup к Content.
- `Строки на всю ширину` - делает строки шириной viewport, чтобы left/right alignment работал нормально.

Дополнительно в каждом `Incoming Layout`, `Outgoing Layout` и `Photo Layout` есть блоки:

- `Container VerticalLayoutGroup` - управляет VerticalLayoutGroup на объекте `Container` spawned-сообщения: padding, spacing, alignment, control child, use child scale и force expand. Это главный блок, если текст не умещается в баббл или уехал из-за старых padding в шаблоне.
- `Container ContentSizeFitter` - задаёт Horizontal/Vertical Fit на `Container`. Обычно `Horizontal Fit = Unconstrained`, `Vertical Fit = Preferred Size`.
- `Background Stretch` - растягивает `Background` по `Container` через stretch anchors. `Stretch offsets Background`: X=слева, Y=сверху, Z=справа, W=снизу; отрицательные значения расширяют фон за пределы контейнера.
- `Background Ignore Layout` - включает `Ignore Layout` у `Background`, чтобы фон не участвовал в VerticalLayoutGroup.
- `Background в начало siblings` - переносит `Background` под текст, чтобы текст и имя рисовались поверх подложки.

## Layout конкретного шаблона

Каждый `Incoming Layout`, `Outgoing Layout`, `Photo Layout` имеет свои поля:

- `Показывать имя` - включает имя внутри этого шаблона.
- `Скрыть аватар` - выключает Avatar/AvatarCircle этого шаблона.
- `Отступ имени снизу` - зазор между именем и бабблом.
- `Сдвиг имени` - X/Y-сдвиг TMP_Text имени.
- `Добавка размера имени` - добавляет ширину/высоту к RectTransform имени, если подпись обрезается.
- `Margin имени` - полный TMP margin имени: X=лево, Y=верх, Z=право, W=низ. Если всё 0, используется `Отступ имени снизу`.
- `Размер шрифта имени` - размер шрифта имени. 0 оставляет размер из шаблона.
- `Переопределить Auto Size имени` и `Auto Size имени` - позволяют включить/выключить TMP Auto Size именно для имени этого типа сообщения.
- `Мин. шрифт имени` / `Макс. шрифт имени` - границы TMP Auto Size для имени.
- `Line Spacing имени` - межстрочный интервал имени. 0 оставляет значение из шаблона.
- `Вертикальный отступ строки` - дополнительный зазор строки.
- `Горизонтальный зазор` - X-сдвиг баббла для конкретного шаблона, если Incoming/Outgoing/Photo override равен `0`.
- `Padding сверху/снизу/слева/справа` - внутренние отступы текста.
- `Макс. ширина` - максимум ширины этого баббла.
- `Мин. ширина` - минимум ширины этого баббла.
- `Сдвиг текста внутри баббла` - X/Y-сдвиг текста относительно padding.
- `Размер шрифта body` - размер шрифта основного текста сообщения. 0 оставляет размер из шаблона.
- `Переопределить Auto Size body` и `Auto Size body` - управляют TMP Auto Size основного текста для конкретного типа сообщения.
- `Мин. шрифт body` / `Макс. шрифт body` - границы TMP Auto Size для основного текста.
- `Line Spacing body` - межстрочный интервал основного текста. 0 оставляет значение из шаблона.
- `Padding строки` - X=лево, Y=верх, Z=право, W=низ у LayoutGroup строки.
- `Сдвиг строки` - двигает всю строку после спавна.
- `Сдвиг баббла` - двигает контейнер баббла внутри строки.
- `Добавка размера баббла` - добавляет ширину/высоту к рассчитанному размеру.
- `Сдвиг аватара` - двигает аватар, если он специально включён.
- `Размер фото` - размер image-вложения.
- `Сдвиг фото` - двигает image-вложение.
- `Выравнивание строки` - left/right/center alignment строки.

## Фото и маленькая “голова”

Quick preview больше не подставляет `Фото по умолчанию` автоматически.

Причина: если в `defaultPhotoSprite` случайно назначена голова/аватар, токен `[фото]` создавал маленькую картинку в переписке. Теперь для этого есть отдельный флаг:

- `Подставлять фото по умолчанию в quick preview`

Оставляй его выключенным, если не тестируешь именно фото-сообщения. Runtime-фото появится только если `PhoneDialogueNode` реально передал Sprite attachment.

## Быстрая диагностика

Если бабблы прилипли к левому краю:

- увеличь `Padding Content сообщений.X`;
- проверь `Строки на всю ширину`;
- проверь `Выравнивание строки` в incoming/outgoing layout.

Если синее/серое перепутано:

- проверь, какой prefab стоит в `Incoming шаблон`;
- проверь, какой prefab стоит в `Outgoing шаблон`;
- проверь, кто указан в quick preview script: контакт или `{PlayerName}`.

Если имя уехало:

- выключи `Показывать имена в бабблах`, если имена не нужны;
- настрой `Сдвиг имени`;
- настрой `Отступ имени снизу`.

Если снова появилась голова:

- включи `Скрывать аватары в бабблах`;
- включи `Скрыть аватар` в incoming/outgoing/photo layout;
- проверь, что `Подставлять фото по умолчанию в quick preview` выключен;
- проверь, что `Фото по умолчанию` не используется как случайная заглушка.

Если текст выходит за подложку:

- увеличь padding нужного шаблона;
- уменьши `Макс. ширина`;
- проверь `Контейнер баббла` и `Текст сообщения`;
- используй `Сдвиг текста внутри баббла` только для тонкой подстройки.

Если preview отличается от runtime:

- нажми `Мигрировать ссылки из StoryUiStyle`;
- нажми `Автозаполнить ссылки телефона`;
- нажми `Проверить ссылки телефона`;
- убедись, что в сцене используется тот же `StoryUserInterface`, который открыт в инспекторе.
